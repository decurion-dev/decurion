# Changelog

All notable changes to Decurion are recorded here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While Decurion is in 0.x, a minor version may include breaking changes.

## [Unreleased]

### Added

- **Plans update in place.** Answer a plan page's questions or ask for changes beside it, and the page dims while your project lead works, then shows the new plan by itself when it's drawn. No more going back to the goal and opening the picture again.
- **One yes per goal.** Typing "yes", "do it" or "go ahead" approves the plan on your screen, or accepts finished work when the agent asked you nothing, and a plan shows **Yes, do it**, **Change something** and **Stop** buttons. You can approve while your project lead is still answering. Each piece that passes its check goes to GitHub as a pull request by itself, since you already approved the plan; pieces that change a protected part still wait for your tap, and the plan marks them up front. The finished goal lists its pull requests in the order to merge them, and closes by itself once they are all merged.
- **One Sign-ins list.** Settings opens with every account Decurion signs in with: Claude A and B, GitHub, how phones reach Decurion, each phone and browser, each cloud worker and each website sign-in. Each has a green, amber or red light and says when it runs out, where that can be known, and your phone gets a reminder a week before.
- **Sign in to Claude from the board.** **Sign in on this PC** next to Claude A or B opens Claude's own sign-in page in your PC's browser and keeps the result in Windows' secure store. No code to copy and paste, and the sign-in is never shown or written to a log.
- **Connect your phone in one click.** In Settings, Phones, **Connect your phone** sets up Tailscale's private https address for Decurion itself and remembers it, so there is no terminal, no setting to type and no restart. If Tailscale needs signing in or HTTPS turned on once, Decurion says so and gives the link.
- **Research, Ask why, and the checker's proof.** Ask a question instead of a change and the project lead plans a research piece: it changes no code, writes a report with each finding marked Checked or Guessed, is never sent to GitHub, and **Turn into a goal** starts work from what it found. **Ask why** under any finished piece gets the project lead's answer from the real change and the agent's log. The checker now lists what it ran and marks its claims checked or guessed, on the goal page and in the pull request. Later pieces of a goal read what earlier ones found.
- **Phone notices you can act on.** Every notice starts with the app's name ("Refill tracker: ready for review"). On Android and the PC, notices carry **Approve plan**, **Accept** or **Open pull request**, so a plain yes needs no trip into the app. Plans waiting for approval and your project lead's questions are now cards in the phone inbox, with **Approve** and **Open plan**.
- **Talk to Decurion, and hear it talk back.** A mic beside every typing box on the phone and the board turns your speech into words in the box; you check them and tap Send. Answer an agent's question by voice, hear replies, questions and reports read aloud, "Read what needs me" on the phone, and Talk mode for a spoken back-and-forth with your project lead. It uses the speech your phone and PC already have, and Decurion never records or keeps sound. Voice settings are in Settings, kept on each device.
- **Master plan.** Each app has one page that lists its goals in your order, each with its steps, the pages agents drew, and what the project lead found along the way. Tick things off, fix one or all of them as a new goal, or add your own to-dos. A Pages tab lists every page agents drew, with the ones that have questions for you marked. Pages now open beside a panel where you answer the agent's questions, approve the plan or ask for changes, on the PC and the phone.
- **One box for new work, on the board and the phone.** "What do you want?" sends it to your project lead, who asks, plans and waits for your approval; or choose **Just do it** for a small change that one agent starts right away. On the phone, tap **New work** on the Board tab. The phone's Board tab also gains an app filter (with two apps or more) and **Show more** in place of the 40-card limit.
- **What next, and the agent's questions first.** Finished work now opens with what the agent asks you, each answer one tap (it goes back to the agent with your answer), then its summary laid out readably (lists and bold, no stray stars), then a "What next?" list saying what Accept, answering and Reject each do. "Fix these" starts new work from what an audit found. Agents are told to end with their questions in a fixed shape so the board and phone can show them as buttons.
- Installers and a release workflow that builds them into a draft GitHub release.
- Built-in help pages that explain each part of Decurion in plain language.
- A design for add-ons, so new kinds of agents and tools can plug in later.
- **Goals on the phone.** The goals page has the phone's bottom tabs, the visual plan opens inside the app with a Back button, the Goals tab shows how many goals wait on you, and you can see and remove what the project lead remembers about an app.
- **Talk to a running agent.** Change its course now, give it a follow-up for when it finishes, or add a note, from the board or the phone. Messages wait safely with the hub until the agent has read them.
- **Tasks within tasks.** Work can belong to a bigger task. Stopping a task stops its smaller tasks first, unless they were set to keep going on their own.
- **Receipts.** Every tap and message carries a receipt number, so a resend after a dropped connection never acts twice, and a tap from an out-of-date screen is ignored.
- **Interrupted, checking.** After a crash the agent is told which step was cut off. A step that only looked at things is redone; one that changed something is checked first, never blindly repeated.
- **ChatGPT and Grok as workers.** Choose Claude, ChatGPT or Grok when you add work. ChatGPT and Grok run through pi, an open-source coding agent, in the same sealed box, and stop at their run's budget.
- **Usage meters and a cap per account.** The board shows how much of each Max plan's week and five hours is used, and what each paid account (Claude pay-per-use, ChatGPT, Grok) spent this month against its own cap.
- **A cap per app.** Each app can have its own monthly cap across all paid AIs, coordinator and review work included.
- **Take over the test browser.** Watch an agent's test browser live from the board or your phone, take control, and hand it back. The browser now runs in a box of its own beside the agent's.
- **Saved website sign-ins.** Sign in once to a site an app needs (a staging admin, a test dashboard) in a sign-in window. Decurion keeps the sign-in encrypted on your PC, never the password, gives it only to that app's runs, and puts a card in your inbox when it needs renewing.
- Contribution guide, security policy, code of conduct, issue and pull request templates, and a cargo-deny configuration for dependency license and source checks.
- **Website limits for agents.** Each agent's container is on its own closed network whose only way out is a small gate. The gate lets through only the AIs (Claude, ChatGPT, Grok), the package stores (npm, PyPI, crates.io) and the websites you add for each app in Settings. Anything else is turned away and shows in the work's activity as a blocked visit. Agents can no longer reach your PC, home network or Tailscale devices. Installers build the gate the first time Decurion starts.
- **Protected parts.** An app can list the parts it wants you to look at yourself in `.decurion/protected-paths`. A piece of a goal that changes any of them waits for you even when the checker passes it. The hub reads the list from the code the work started from, so the agent cannot take anything off it, and holds the piece if it cannot tell. Coordinators and builders now also read an app's AGENTS.md or CLAUDE.md first.
- **Agents can build and test Rust apps.** Claude agents' containers now come with Rust 1.99.1 (with its format and lint tools) and a C compiler, so an agent working on Decurion itself, or any other Rust app, can run its build, lint and test checks before it finishes. Downloaded libraries come only from crates.io and are kept between runs of the same piece of work. Decurion rebuilds the container the first time it starts after the update, which takes a few minutes longer than usual, and a cloud worker updates itself to match.
- **Settings on your phone.** The phone's Settings tab now has everything the board's Settings has: apps and their websites, caps, test keys, the GitHub token, website sign-ins and pairing. It also shows this month's usage at the top, has the Pro view switch, and marks which paired device is the phone you are holding.
- **Accepted work goes to GitHub.** When you tap Accept, the hub pushes the work from your app's folder, with this PC's own GitHub sign-in, to a new `decurion/...` branch, and opens a pull request that says what was done, what the checker found and what was held. Without a GitHub token (Settings, GitHub) you get a button that opens the pull request in one tap. It never pushes to the main branch, never overwrites a branch and never merges: you merge on GitHub. If sending fails, the work stays accepted, the card says why, and Try again sends it. Agents never get the token or a way to push.
- **Choose an app's folder from a list.** When you add an app, you can pick its folder from the folders on your PC instead of typing the path, on the board or on your phone. Git app folders are marked. The list shows only folder names, and only inside your usual code folders (such as Projects and Documents) and the folders your apps are in, never Decurion's own data.
- **Files for agents.** Attach a brief, a spec, a price list or a photo to an app (Settings) or to one goal (its Files tab, or the paperclip by the message box), from the PC or the phone. Agents get copies each time they start; Word, Excel and PowerPoint text is taken out for them, and they read PDFs and pictures directly. Up to 25 MB a file, and 100 files or 250 MB for each app. The originals stay on your PC and reach GitHub only if an agent puts one in the app's code on purpose.
- **Answer questions right on the page.** The designer's visual plan and the checker's "as built" page can ask you yes or no, a choice, or something in words, and you answer beside the page instead of going back to the chat. Your answers reach your project lead as a message from you. Pages still run nothing: Decurion draws the answer buttons itself. A checker's page for a report or audit is now a readable write-up of what it found.
- **A master plan for each app.** One checklist of an app's goals, each with its steps ticked off as the work moves, and the to-do items found along the way. When an audit or other work finds things still to do, the project lead lists them under that goal. Tick them, drop them, reword them, put them in your own order, add your own, or pick some and start one goal to fix them; closing that goal ticks them off.

### Changed

- **Stay signed in.** You confirm "Sign in to Decurion" only the first time; after that, starting Decurion opens the board directly. A phone or browser you use stays signed in instead of signing out after a year.
- **Pay-per-use until the plan resets.** One tap on **Continue on pay-per-use** now keeps that Max plan's Claude work, new work, planning and checking included, on pay-per-use until the plan resets, then goes back to the plan by itself. It still counts toward the monthly cap. The board and phone say "running on pay-per-use until" instead of asking again.

### Fixed

- **Apps with very long file names.** On Windows, a goal or piece of work on an app with a file whose full path passed 260 characters stopped with "Filename too long" before it started. Decurion now copies those apps whatever the PC's own Git settings say.

## [0.1.0] - Unreleased

The first version: Claude Code agents running in sealed containers on your PC, on one board, with an approvals inbox on your phone. Windows first.

### Added

- **Sealed agent containers.** Each piece of work runs Claude Code in its own Docker container with its own copy of the code. The only credential inside is the Claude token for that app's profile (A or B), kept in Windows Credential Manager. GitHub, AWS and other keys never enter the container, and the host's `~/.claude` folder is never mounted.
- **The board.** The hub keeps apps and work in SQLite, allows only valid state moves, keeps an append-only audit log, and serves a board page. Work moves to *In review* only when the agent has actually committed to its branch, counted in a runner-owned bare repository so git never runs on the agent's own config. Agents cannot move their own cards.
- **Phone inbox.** Pair a phone by scanning a one-use QR code that expires after 30 minutes. The `/inbox` page lists only what needs you (In review, Needs you, Failed) with plain explanations and Accept, Send back, Reject and Retry buttons. Signed-in devices survive hub restarts and can be removed from the board.
- **Phone notifications.** Encrypted Web Push alerts whenever work needs you, carrying only a short line and a link to the inbox.
- **Crash-safe restarts.** Every run event is saved before the board shows it. After a crash the runner requeues its in-flight work and resumes the same Claude Code session, and a restarting runner stops containers a dead runner left behind.
- **Monthly pay-per-use spending cap.** Apps can run on an Anthropic API key instead of a Max account. Decurion sets money aside before each pay-per-use run, passes a budget to Claude Code, and stops pay-per-use work at its monthly cap (default $100), moving it to *Needs you* with a phone alert. The board shows this month's spend against the cap and what Max runs were worth.
